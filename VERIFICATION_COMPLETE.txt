def _validate_sql_identifiers(fields: dict[str, Any]) -> None:
    """Validate all field names against strict SQL identifier pattern.

    Raises ValueError if any key is not a valid SQL identifier (pattern: ^[A-Za-z_][A-Za-z0-9_]*$).
    """
    import re
    pattern = re.compile(r'^[A-Za-z_][A-Za-z0-9_]*$')
    for k in fields:
        if not pattern.match(k):
            raise ValueError(f"invalid field name: {k!r}")

SECURITY ANALYSIS
================================================================================

VULNERABILITY FIXED:
  Before: update_task() and update_contender() interpolate field names
          directly into SQL strings without validation:
          cols = ", ".join(f"{k}=?" for k in fields)
          _execute(f"UPDATE tasks SET {cols} WHERE id=?", ...)
  
  Attack: update_task(1, **{'status; DROP TABLE tasks; --': 'x'})
          Would generate: UPDATE tasks SET status; DROP TABLE tasks; --=? WHERE id=?

SOLUTION APPLIED:
  After: Validation function checks all field names FIRST:
         _validate_sql_identifiers(fields)  ← Prevents attack
         cols = ", ".join(f"{k}=?" for k in fields)
         _execute(f"UPDATE tasks SET {cols} WHERE id=?", ...)
  
  Result: Same injection attempt now raises ValueError immediately
          and never reaches SQL execution layer.

ATTACK VECTORS BLOCKED:
  ✅ SQL command injection (DROP TABLE, DELETE, etc.)
  ✅ SQL comment injection (-- and /* */)
  ✅ Stacked queries (multiple statements with ;)
  ✅ Quote escaping (trying to break out of SQL)
  ✅ Parenthesis injection (closing SET clause early)
  ✅ Special character injection (., @, [, ], -, etc.)
  ✅ Whitespace injection
  ✅ Leading digit identifiers (invalid in SQL)
  ✅ Empty identifier injection

RISK LEVEL: CRITICAL → RESOLVED ✅
  Before fix: High risk of arbitrary SQL execution
  After fix: All identifier-based attacks blocked at validation layer

TECHNICAL DETAILS
================================================================================

Validation Pattern: ^[A-Za-z_][A-Za-z0-9_]*$

Breakdown:
  ^           Start of string
  [A-Za-z_]   First char: letter (uppercase/lowercase) or underscore
  [A-Za-z0-9_]* Following chars: letters, digits, or underscores (zero or more)
  $           End of string

Valid Examples (match pattern):
  - status            (standard field)
  - _internal         (underscore prefix for internal fields)
  - field_name_123    (letters, numbers, underscores)
  - CamelCase         (mixed case is fine)
  - id                (short field names ok)

Invalid Examples (don't match):
  - 123field          (starts with digit)
  - field-name        (hyphen not allowed)
  - field.name        (dot not allowed)
  - field@name        (@ not allowed)
  - field name        (space not allowed)
  - field;delete      (semicolon not allowed)
  - field)or(1        (parentheses not allowed)
  - "quoted_field"    (quotes not allowed)
  - (empty string)    (empty not allowed)

Implementation: Python `re.compile(r'^[A-Za-z_][A-Za-z0-9_]*$')`
